### Лебедь 5

Описание события:

Десять партнёров продают сервер под собственными марками и обновляют своих клиентов по собственным графикам, поэтому в эксплуатации одновременно находятся шесть версий. Ваши выпуски выходят чаще, чем партнёры готовы их принимать, а вторая линия обязана поддерживать все версии под единый пакет «Премиум» с круглосуточной реакцией. Партнёры не берут на себя обязательств по качеству собственной первой линии, но эскалируют всё как аварии. Метрики по выпускам оказываются несопоставимыми между партнёрами, а нагрузка на вторую линию растёт с каждой новой версией.

Реакция на событие:

1. Наиболее опытных штатных Специалистов технической поддержки (L1) подключаем к разбору обращений от указанных партнеров. 
2. Находим компанию-аутстаффера, и через нее "арендуем" 1,5 FTE специалиста уровня L1, на 6 мес с возможностью пролонгации для выполнения обязанностей Специалистов технической поддержки (L1). В соответствии с SLA пункт 4.1.2 компания имеет право привлекать подрядные организации, если это требуется для обеспечения согласованного уровня сервиса и(или) для решения запросов Заказчика.
3. Добавить в веб интерфейсе администратора скрипт проверяющий версию и в случае, если версия используемого продукта меньше актуальной выводить сообщение о необходимости обновления. Пример: "Вы используете устаревшую версию продукта, отсутствие последних обновлений безопасности делает систему уязвимой!". Доработка небольшая и может быть реализована в ближайшем релизе.
4. Делать рассылки о выявленных уязвимостях в предыдущих версиях продукта после выхода исправления. В получатели включать представителей информационной безопасности клиента. (Пояснение: Цель - найти заинтересованных в поддержании продукта в актуальном состоянии внутри компании клиента).

Правки в регламент управления ИТ:
- Расширен пункт про информирование клиентов о выявленных уязвимостях и их исправлении. Рассылка будет производиться ответственному по договору + представители информационной безопасности клиента;
- В каталог услуг добавлен отдельный тип услуги "Проблемы с информационной безопасностью продукта"



### Лебедь 3

Описание события:

Критическая уязвимость требует срочного патча, который нужно собрать и опубликовать на портале загрузок. Доступ в продуктивную среду портала по-прежнему согласуется около сорока минут и с записью сессии, а по соглашению ночное обращение первого приоритета нужно взять в работу за пятнадцать. Заказчики с уязвимой установкой требуют патч в течение нескольких часов, служба безопасности — не ускорять согласование. Выпуски по плану ждут, пока команда разберётся с этим, и сдвигаются.

Реакция на событие:

Аналогичная ситуация была рассмотрен в Практической работе №3, чёрный лебедь №5.  

В регламенте управления ИТ-сервисом есть процедура экстренного доступа.
"В случае если по каким-либо причинам нет возможности получить согласование Специалиста по ИБ либо в случае возникновения экстренной ситуации работы могут быть проведены без согласования ИБ, но под контролем Руководителя ИТ-инфраструктуры либо Технического лидера (зависит от зоны ответственности за продуктовую систему)."

Выпускаем экстренный патч для устранения уязвимости, не дожидаясь согласования ИБ. Работы проходятся под личным контролем Технического лидера. Сроки релиза 6 сдвигаются. Служба безопасности сможет ознакомиться с записью сессии после проведения работ в любое удобное время.
